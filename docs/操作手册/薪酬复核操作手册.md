# 薪酬复核操作手册

> **适用账号**：`hr02`（角色「薪酬复核」）
> **这本手册解决什么**：工资表锁不锁、解锁不解锁，以及锁定前那几分钟到底看什么。
> **核心原则**：复核不是"再看一遍"，而是**对锁定的后果负责**——锁定后数据写保护、进入报表和个税累计，要改只能解锁并留审计。

---

## 0. 一页速查：你能做什么 / 不能做什么

| ✅ 你能做 | ❌ 你不能做（当前版本） |
|---|---|
| 查看人员、工资项、期间、编制台、报表、个税核对 | 改人员、改薪酬档案、改编制台（你没有编辑权限） |
| **锁定**「编制中」的期间、**解锁**「已锁定」的期间（必须填原因） | 新建期间、触发生成、导入绩效（都是薪酬专员的事） |
| 导出工资表、工资条、月/年报、个税表 | 查看完整证件号/手机号（你没有敏感字段权限） |
| 按部门/员工筛选、核对合计与个税累计 | 自己打开生成结果弹窗（只有点「生成」才出现，需专员提供） |
| 看到期间状态自动刷新（15 秒） | 修改个税、社保参数或台账 |
| —— | 审批流/待办、双人复核、批量锁定、审计日志界面 |

**你要守住的一条线**：**编制人 ≠ 锁定人**。这条是系统硬校验，换不了、绕不过。

---

## 1. 登录与你看到的界面

1. 打开系统地址，输入 `hr02` 的账号密码登录。
2. 登录后同样落在「**工资期间**」。
3. 与专员相比，你的界面差异：
   - 「人员管理」没有「新增人员」「批量导入」「编辑」；
   - 「工资期间」没有「新建期间」「生成」「导入」；
   - 编制台顶部有黄色提示「当前账号没有 payroll:record:edit 权限，编制台为只读」，双击不能编辑，「保存修改」不可用；
   - 期间行上你会看到「**锁定**」（编制中）或「**解锁**」（已锁定）。

> 右上角灰色标签是数据范围代码（`ALL` = 集团全部主体），不是工资状态。

## 2. 复核要点清单（锁定前逐项过）

| # | 检查项 | 在哪里看 | 不通过怎么办 |
|---|---|---|---|
| 1 | **状态是「编制中」**，最近一次生成成功 | 工资期间列表 | 还是「草稿」= 没生成；找专员 |
| 2 | **跳过名单处理了吗** | 生成结果弹窗（专员侧） | 让专员补薪酬档案/离职日期后重新生成 |
| 3 | **失败人数 = 0** | 专员提供的生成结果弹窗；或尝试锁定时系统会报出失败人数 | 有失败先处理并重新生成；不处理锁不了 |
| 4 | **人数合理** | 期间列表「人数」对比上月 | 人数骤降/骤升，先问专员 |
| 5 | **合计与明细一致** | 编制台底部「应发/扣款/实发」+ 期间列表 | 点「刷新」再比；仍不一致就查原因 |
| 6 | **变动项无明显异常** | 编制台按部门筛选抽查 | 大额、负数、整月为 0 的要问清楚 |
| 7 | **社保/公积金/个税列** | 编制台「社保个人/公积金个人/个人所得税（扣）」 | 全员为 0 → 可能没配参保；只有个别人 0 看是否未参保 |
| 8 | **个税累计口径** | 个税核对页 | 见第 5 节 |

补充说明：

- **跳过名单关掉就没了**（当前版本没有回看入口）。复核时让专员把生成结果的截图/名单发给你，或当场一起看。
- 跳过 ≠ 失败：跳过是"按规则不算"（未配档案、离职日期缺失、未入职），失败是"该算算错了"。**失败 > 0 时系统禁止锁定**。
- 你看到的编制台是**只读**的，发现错也只能让专员改，改完你重锁。

## 3. 锁定操作

1. 「工资期间」→ 找到该期间（状态「编制中」）→ 点「**锁定**」。
2. 弹窗提示：「锁定后 YYYY-MM 将禁止编辑，且锁定人不能是本期编制人。确认锁定？」→ 点「**锁定**」。
3. 成功后提示「**期间已锁定**」，状态标签变绿色「已锁定」。

系统会按顺序校验，遇到这些提示说明还不能锁：

| 提示 | 含义 | 处理 |
|---|---|---|
| 期间尚未生成，只有编制中的期间可以锁定 | 还是草稿 | 让专员先生成 |
| 期间正在生成，请等待完成后锁定 | 生成任务没跑完 | 等批次 SUCCESS 再锁 |
| 上次生成有 N 人失败，请先处理再锁定 | 有失败员工 | 让专员处理/重新生成 |
| 最近一次生成未成功（FAILED），请先重新生成再锁定 | 最近一批失败 | 让专员重新生成 |
| 锁定人不能是本期间的编制人，请由他人复核锁定 | 你是本期编制人 | 换一位复核员锁 |
| 期间已锁定，无需重复锁定 | 已被别人锁了 | 刷新确认即可 |
| 期间已归档，不能锁定 | 归档状态 | 无需操作（归档当前不可达） |

锁定后发生什么：

- 期间变为**写保护**：任何人改工资都会被服务端拒绝（不只是界面灰掉）。
- 工资记录状态变为"已确认"，进入月度/年度报表统计。
- 本期数据**累加进个税年度累计台账**（这是下个月个税计算的基础）。
- 可以导出工资表/工资条了。
- 锁定动作写审计（谁、何时、哪一期）。

## 4. 解锁操作

### 4.1 什么时候该解锁

- 锁定后发现算错/漏人/重复；
- 薪酬档案、参保信息、专项扣除补录后需要重算；
- 政策口径变更需要重做；
- 个税累计明显错误需要重算。

**不要为了"看一眼"或"微调一个数"就解锁**——解锁会把这个期间从报表和个税累计里撤出来，直到你重新锁定。

### 4.2 怎么解锁

1. 「工资期间」→ 状态「已锁定」的期间行 → 点「**解锁**」。
2. 弹窗「解锁期间（高危）」→ 填「**解锁原因**」（必填，最多 255 字，会写进审计）。
3. 点「**确认解锁**」→ 提示「期间已解锁，回到编制中」。

规则：

- 只有「已锁定」能解锁；「编制中」不需要解锁；「已归档」不可解锁。
- 原因不填会被前端拦（"请填写解锁原因"），后端也会返回"解锁原因必填"。
- **只有持有解锁权限的角色能操作**；薪酬专员没有该权限，尝试解锁会被拒绝。
- 解锁后：期间回到「编制中」，工资记录回到草稿状态，**本期从个税累计台账中减回**，报表/年度/个税不再统计这一期。

### 4.3 解锁后必须做的事

1. 通知专员修改/重新生成/重新导入；
2. 重新走一遍第 2 节清单；
3. **重新锁定**。没重新锁定之前，这一期等于"没结账"。

## 5. 个税核对的复核视角

入口：左侧「**个税核对**」。

1. 年度默认是**上一年**，先改成本年。
2. 可按部门/员工查；点「查询」。
3. 重点看四件事：

| 看什么 | 正常 | 异常信号 |
|---|---|---|
| 计薪月数 | 与该员工实际发薪月数一致 | 年中入职却从 1 月算起 / 离职后还在增加 |
| 累计减除 | = 5,000 × 计薪月数 | 对不上说明月份口径有问题 |
| 累计社保/公积金 | 与参保信息和编制台扣款列一致 | 有参保却为 0；没参保却有数 |
| 税负率 | 累计已预扣 ÷ 累计收入，随收入档位变化 | 年初异常高、或全年恒定不变 |

注意：

- **税负率不能加总**，合计行显示「—」，不要拿合计行去除。
- 只统计**已锁定/已归档**期间；页面提示"YYYY-MM 已有工资数据但未锁定"是正常的，锁定后才会纳入。
- 个税是**累计预扣**：下半年税额比上半年高是正常现象，不要按"当月收入 × 税率"去质疑。
- **解锁会影响累计**：解锁 → 重算 → 重锁，累计会重新生成；核对时以最后一次锁定后的数据为准。
- 个税功能上线前的历史期间没有累计台账；年中上线需要实施人员补期初累计，否则会从上线当月重新起算。

---

## 6. 复核员的红线

1. **不碰数据**：你没有编辑权限；所有修改由专员做，你只负责锁/解锁。
2. **不锁自己编制的期间**：系统会拦；也不要找人"代点"，内控意义就在这里。
3. **失败未清零不锁**：锁了就等于把漏算的人永久排除在本期之外。
4. **解锁必须写真实原因**：原因进审计，是事后追责的依据。
5. **解锁后必须重锁**：否则报表少一期、个税累计缺一期，后面很难发现。
6. **导出即留痕**：每次导出都写审计；不要用它绕开权限给外部导数据。

---

## 7. 当前版本不支持的复核能力（如实说明）

- 没有**审批流/待办**：锁定是本人直接在页面上操作，不走工单；
- 没有**双人复核**或"复核意见"字段；
- 没有**批量锁定/批量解锁**（一期一期点）；
- 没有**审计日志查询界面**（锁定/解锁/导出/改数都有记录，但要在数据库/找开发查）；
- 没有"未生成人员清单"的独立页面，跳过名单只存在于生成那一刻；
- 没有导出前的**合计行校验报告**，需要自己比对编制台与期间列表；
- 不能查看完整证件号/手机号（无敏感字段权限）。
