# 系统管理员操作手册

> **适用账号**：`admin`（角色「系统管理员」）
> **这本手册解决什么**：开账号、配权限、维护部门和主体、改系统参数，以及什么情况下必须找开发。
> **最重要的边界**：系统管理员**只管理系统，不碰工资**。你没有薪酬查看/编辑/导出权限，登录后也看不到工资页面——这是有意的"三权分立"。

---

## 0. 一页速查：你能做什么 / 不能做什么

| ✅ 你能做 | ❌ 你不能做（当前版本） |
|---|---|
| 新建用户、分配角色、停用/删除用户、重置密码 | 查看任何人的工资、编制台、报表 |
| 新建/编辑角色，勾选权限点 | 锁定/解锁工资期间 |
| 授予/收回「集团全部主体（ALL）」数据范围（需 `sys:role:grant:all`） | 导入工资数据、导出报表 |
| 维护部门树、法人主体 | 查看完整证件号/手机号（无敏感字段权限） |
| 修改系统参数（计薪天数、工龄单价、法定节假日） | 修改个税税率表、社保/公积金比例（界面没有入口） |
| 给薪酬角色授予「查看敏感字段」权限 | 查看审计日志界面（记录在库里，没有页面） |
| 通过停用账号完成人员离岗 | 归档工资期间、修正已锁定期间的数据 |

**记住**：你能决定"谁能看工资"，但你自己看不到工资。这个设计是为了防止"管理员顺手改一笔"。

## 1. 登录与界面

1. 浏览器打开系统地址，输入 `admin` 的账号密码 → 「登 录」。
2. 登录后默认落在「**用户管理**」（不是工资期间）。
3. 左侧只有一组菜单：「**系统管理**」，下含：
   - 用户管理
   - 角色与授权
   - 部门管理
   - 法人主体
   - 系统参数
4. 右上角灰色标签是你的数据范围代码（`ALL`）。

> 如果登录后提示"无可用页面"或反复跳 403，说明账号没有任何可用权限，找另一位管理员检查角色。

---

## 2. 开账号 SOP（最常用）

> 目标：给一个新同事开通"薪酬专员"账号，并确认他能正常登录、看到该看的菜单。

### 2.1 建用户（先不挂角色）

1. 「系统管理」→「**用户管理**」→ 右上「**新增用户**」。
2. 填写：

| 字段 | 必填 | 说明 |
|---|---|---|
| 用户名 | 是 | 登录名，**创建后不可修改**；建议用 `姓名拼音/工号`，全公司统一规则 |
| 初始密码 | 是 | 至少 8 位，最长 128 位；**用户不能自助改密**，以后改密也只能由管理员「重置密码」 |
| 姓名 | 是 | 真实姓名，用于审计显示 |
| 法人主体 | 是 | **创建后不可修改**；决定这个账号属于哪家公司 |
| 部门 | 否 | 只列该主体下的部门；**部门主管必须填**（见 2.3） |
| 关联人员 | 否 | 填**系统内部人员 ID**（不是工号）；普通员工角色靠它关联到自己的工资记录 |
| 角色 | 否 | **本步骤先留空**，保存后再分配（便于确认"无角色也能建号"） |
| 状态 | 是 | 默认「启用」 |

3. 点「**保存**」→ 提示「已创建用户 xxx」。

### 2.2 分配角色

1. 在用户列表找到刚建的账号 → 行内「**编辑**」。
2. 在「角色」下拉里选择（可多选）：
   - 薪酬专员（`PAYROLL_CLERK`）
   - 薪酬复核（`PAYROLL_REVIEWER`）
   - 部门主管（`DEPT_MANAGER`）
   - 普通员工（`EMPLOYEE`）
   - 系统管理员（`SYS_ADMIN`）
3. 点「**保存**」→ 提示「已更新用户 xxx」。

> 也可以在「新增用户」时直接选角色；两种方式等价。**建议仍按"先建号、再分配"**，这样出问题时容易判断是建号失败还是授权失败。

### 2.3 三个必须注意的点

- **部门主管必须填「部门」**。该角色的数据范围是"本部门及下级"，没填部门时登录后几乎看不到任何数据。
- **普通员工必须填「关联人员」**。这个字段要的是人员档案的内部 ID，不是工号；当前界面是手输框，没有选择器。填错会导致员工看不到自己的工资。
- **角色是按主体建的**。默认只有「默认主体」下有 5 个内置角色；给新法人主体开号前，要先去「角色与授权」为该主体建角色并授权，否则角色下拉是空的。

### 2.4 验证

1. 让本人用新账号登录。
2. 核对菜单是否符合角色（见第 3 节速查表）。
3. 若菜单缺失：回到「用户管理」看角色是否保存成功；再看「角色与授权」里该角色是否勾了对应权限点。
4. 权限改动**对新请求立即生效**；如果对方页面还停在旧菜单，让他刷新或重新登录。

### 2.5 日常账号维护

| 操作 | 路径 | 说明 |
|---|---|---|
| 改姓名/部门/关联人员/状态/角色 | 用户管理 → 编辑 | 用户名、法人主体不可改 |
| 重置密码 | 用户管理 → 重置密码 | 旧密码立即失效，旧登录态也失效，对方需重新登录 |
| 停用 | 用户管理 → 编辑 → 状态「停用」 | 停用后无法登录；**离岗优先停用，不要直接删** |
| 删除 | 用户管理 → 删除 | 逻辑删除，历史审计保留；有关联数据时可能被拒 |
| 自我保护 | —— | **不能停用/删除自己**（系统会拒绝） |

## 3. 权限速查表：五个角色

| 角色 | 数据范围 | 能做什么 | 不能做什么 |
|---|---|---|---|
| **薪酬专员** `PAYROLL_CLERK` | 集团全部主体 | 建期间、生成、导入、编制台改数、建人/调薪/离职/调动、参保与专项扣除、查看敏感字段、导出、看全部报表与个税 | 锁定/解锁、管理系统、改工资项字典以外的系统配置 |
| **薪酬复核** `PAYROLL_REVIEWER` | 集团全部主体 | 查看全部工资、**锁定/解锁**、导出报表、看个税核对 | 建期间、生成、导入、改任何工资数据、建人、看敏感字段 |
| **部门主管** `DEPT_MANAGER` | 本部门及下级 | 查看本部门人员、工资期间、编制台（只读）、月/年报、个税核对 | 任何写操作、导出、看其他部门/全公司、看敏感字段 |
| **普通员工** `EMPLOYEE` | 仅本人 | 查看自己的工资期间/报表/个税（靠「关联人员」定位） | 看他人、任何写操作、导出 |
| **系统管理员** `SYS_ADMIN` | 集团全部主体 | 用户、角色、部门、主体、系统参数 | **看不到任何工资页面**，不能锁定/导出/改工资 |

补充：

- 一个人可以挂多个角色，数据范围取**最宽**的；权限点取**并集**。
- 内置角色不满足业务时，可以新建角色（如"薪酬专员（单主体）"），再按需勾权限。
- 「部门主管」是**只读**角色。如果你给他加"编辑核算"，他就能改本部门下属的工资——从内控角度通常不可接受，加之前请业务负责人书面确认。
- 「工资项」字典的新增/修改由「编辑核算」权限控制，所以**薪酬专员可以维护工资项**；系统管理员反而看不到该菜单。

## 4. 角色与授权

### 4.1 新建角色

1. 「角色与授权」→「**新增角色**」。
2. 填：角色编码（英文，如 `PAYROLL_CLERK_SH`）、角色名称、**数据范围**、备注、状态。
3. 数据范围五选一：

| 显示名 | 代码 | 含义 |
|---|---|---|
| 集团全部主体 | `ALL` | 所有法人；**授予它需要 `sys:role:grant:all`** |
| 本公司全部部门 | `COMPANY` | 当前主体全部部门 |
| 本部门及下级 | `DEPT_SUB` | 部门树向下包含 |
| 本部门 | `DEPT` | 仅本部门 |
| 仅本人 | `SELF` | 只能看自己 |

4. 保存后，在列表行点「**授权**」。

### 4.2 授权（勾权限点）

「授权 · 角色名」弹窗按两个模块分组：

- **核算与薪资**：查看核算、编辑核算、锁定期间、解锁期间、导入工资数据、导出报表、查看敏感字段
- **系统管理**：查看用户、编辑用户、查看角色、编辑角色、授予集团数据范围、编辑部门、编辑法人主体、查看系统参数、编辑系统参数

勾选 → 点「**保存授权**」→ 提示「权限点已更新」。

规则（防止自我提权）：

- 你**不能授出自己没有的 `sys:*` 权限点**；
- 你**可以**给薪酬角色授予 `payroll:*`（系统管理员本来就不持有薪酬权限），但**不能加到自己所在的角色上**；
- 但**不能把带薪酬权限的角色挂到自己账号上**（保存用户时会拒绝："不能给自己授予薪酬权限"）；
- 授予 `ALL` 数据范围需要 `sys:role:grant:all`；
- 删除仍有关联用户的角色会被拒绝（先把人换角色）。

### 4.3 授权后的验证

让目标用户重新登录，检查菜单和按钮：
- 只有「查看核算」→ 所有页面只读，无保存/导出按钮；
- 有「编辑核算」→ 编制台可编辑、人员可新建/编辑、工资项可维护；
- 有「导入工资数据」→ 期间行出现「导入」；
- 有「导出报表」→ 各页出现「导出 xlsx / 导出工资表」；
- 有「查看敏感字段」→ 人员列表证件号旁出现"眼睛"图标。

## 5. 系统参数

入口：「系统管理」→「**系统参数**」。

| 参数（界面显示） | 默认值 | 作用 | 改了什么时候生效 |
|---|---|---|---|
| 月平均计薪天数（`payroll.monthly-payable-days`） | 21.75 | 入离职不足整月的折算分母 | **下次生成/重算**时生效；已生成的记录不变 |
| 工龄工资：每满一年金额（`payroll.seniority-pay-per-year`） | 100 | 每满一年发多少元 | 同上；重算后历史期间也会按新单价重算 |
| 法定节假日（`payroll.calendar.holidays`） | 空 | 逗号分隔的 `YYYY-MM-DD`；用于折算工作日 | 下次生成/重算时生效 |
| 系统版本号（`payroll.system-version`） | 1 | 运维用 | **只读**，不能改 |

操作：

1. 行尾「**编辑**」→ 输入新值 → 「**保存**」→ 提示「**已保存，下次生成工资时生效**」。
2. 数值类只能填数字；日期列表保存前会逐项校验，格式错会提示。
3. 只读参数（灰色「只读」标签）不能编辑。

注意：

- 参数**不会自动重算已有工资**。改完要让薪酬专员对相关期间重新「生成」。
- **法定节假日为空时**，生成会提示"法定节假日未配置，折算天数可能偏多"——这不是错误，但折算结果会偏大，建议按国务院放假安排补齐。
- 工龄单价一改，**所有重新生成的期间**都按新单价算；如果只想影响未来月份，请在下月生效前改。
- 页面上的「警示」列如果有黄字，先读一遍再改。

## 6. 部门与法人主体

### 6.1 部门管理

入口：「部门管理」→ 先选「**法人主体**」。

- 新增根部门：右上「**新增根部门**」。
- 新增下级：行内「**新增下级**」。
- 编辑：改上级部门、部门编码、部门名称、排序、状态。
- 删除：有下级部门、或有关联员工/用户时会被拒绝（提示"存在下级部门…"），要先把人/子部门迁走。

字段规则：

- 部门编码在**同一主体内唯一**，员工批量导入用的就是它（不是名称）。
- 排序值越小越靠前。
- 停用的部门不会再出现在下拉里，但历史工资快照不受影响。

### 6.2 法人主体

入口：「法人主体」。

- 「新增主体」：主体编码（全局唯一）+ 主体名称 + 状态。
- 编码重复会提示冲突；创建后可改名称/状态，但**工资期间与工资表按主体隔离**，不要把已有主体随意改名当成"合并"。
- 新主体下**没有部门和角色**，要先建部门、建角色，才能给它开账号、建人员。

> 如果发现月度/年度报表里只有「默认主体」有数、其他主体全空，通常不是报表坏了，而是**工资数据都挂在默认主体**（历史数据归属问题）。这属于数据治理，需要开发协助，界面改不了。

## 7. 敏感字段（证件号/手机号）的授予与审计

### 7.1 现状

- 人员列表默认只显示掩码：证件号 `****1234`、手机号 `138****8000`。
- 只有持有 `payroll:sensitive:view`「查看敏感字段」的账号，才会在证件号旁看到"眼睛"图标。

### 7.2 怎么授予

1. 「角色与授权」→ 找到「薪酬专员」角色（或自建角色）→「**授权**」。
2. 在「核算与薪资」组勾选「**查看敏感字段**」→「保存授权」。
3. 让该角色用户重新登录。

### 7.3 审计含义（必须向业务说清楚）

- 用户点"眼睛"时会先弹二次确认：「查看完整证件号会记录审计日志，确认查看？」
- 确认后弹窗显示该员工的**完整证件号与手机号**，顶部红字「本次查看已记入审计日志」。
- 系统**每次调用都写审计**（谁、什么时候、看了谁）。
- 当前**没有审计查询界面**，要查记录只能找开发/DBA。
- 因此：只授予真正需要办参保、开卡、签合同的岗位；不要给全员开放。**没有"只查看某一个人"的细粒度权限**，给了就是全公司可看。

## 8. 什么情况必须找开发（超界操作）

| 场景 | 为什么界面做不了 | 找谁/怎么处理 |
|---|---|---|
| 已锁定期间发现数据错误 | 没有"更正单/补发扣回"功能，只能解锁重算且旧版本不留 | 先让复核员解锁，改完重锁；需要留痕的补发扣回找开发评估 |
| 解锁按钮点了没反应/提示无权限 | 解锁权限只给复核角色；或期间不是「已锁定」 | 先核对角色；仍不行找开发查审计与状态 |
| 查审计日志 | 没有页面 | 由开发/DBA 在数据库中查询审计记录 |
| 调整个税税率表、社保/公积金比例或基数上下限 | 系统参数页没有这些入口 | 开发改参数表 |
| 年中上线个税，需要补期初累计 | 界面没有期初录入 | 开发执行升级脚本中的期初累计 SQL |
| 归档工资期间 | 状态机有 `ARCHIVED`，但当前没有入口 | 暂不提供；需要留存找开发 |
| 批量调整社保基数（每年 7 月） | 没有批量入口 | 逐个员工新增参保区间，或找开发 |
| 跨主体调动、合并主体 | 界面不支持跨主体调部门 | 走"离职 + 新主体入职"或找开发评估 |
| 报表/页面报"服务器内部错误" | 后端异常 | 记录时间、账号、操作，找开发看日志 |
| 角色授权提示 403 / 权限点异常 | 防提权规则或数据异常 | 先确认自己没有越权授予 `sys:*`；仍不行找开发 |

## 9. 安全与运维习惯

1. **一人一号**，不要共用 `admin`；离岗当天停用。
2. 初始密码至少 8 位；**用户无法自助改密**，需要更换时由管理员重置（重置后旧密码和旧登录态立即失效）。
3. 连续输错密码会触发临时限制（约 5 次后 429），稍等再试，不要反复刷。
4. 只给最小权限：能看汇总就不给编辑，能编辑就不给导出，能导出就不给敏感字段。
5. **不要给自己加薪酬角色**（系统会拦），也不要用管理员账号做工资操作。
6. 改系统参数前先记录原值；参数影响下一次生成，改错要能改回。
7. 定期检查：离职人员是否停用、兼任角色是否仍必要、`ALL` 范围是否只留给集团 HR/审计。

## 10. 当前版本不支持的管理能力（如实说明）

- 没有审计日志查询页面；
- 没有登录日志/在线用户/强制下线；
- 没有密码策略配置（长度、复杂度、有效期），也没有用户自助改密/强制首次改密（改密只能由管理员重置）；
- 没有批量导入用户（只能一个个建）；
- 没有角色复制、权限模板；
- 没有"关联人员"选择器（只能手输内部 ID）；
- 没有数据备份/恢复入口（属运维层）；
- 没有工资期间归档入口；
- 个税/社保参数不可在界面维护。
