## 失败与存疑汇总

**❌ 失败 3 条**
1. **16b 越权管理高权账号**：仅 COMPANY 范围、持有 `sys:user:edit` 的账号，可对 ALL 范围的 SYS_ADMIN 账号执行改名/停用/删除，均返回 200 并落审计。`UserAdminService.update/delete` 缺少 `assertCanManageAccount`（只有 `resetPassword` 有）。
2. **19b 部门可挂不存在的主体**：`POST /depts` 传一个不存在的 `companyId` 仍创建成功，产生孤儿组织数据。
3. **15b 不存在期间导出空表**：`PERIOD_SHEET`/`PAYSLIP` + `2099-01` 返回 200 空工作簿，与本任务"不要空表 + 200"的口径冲突，用户会误判该期间没有工资。

**⚠️ 存疑 3 条**
1. **18b 授权模型死锁**：由于"只能授出自己持有的权限"，而种子角色中 `sys:*` 与 `payroll:*` 完全不相交，实际结果是**任何账号都无法创建/授权薪酬岗用户**。机制本身符合要求，但缺少一个"全权管理员"角色会导致上线后无法开号。
2. **9b 月度导出编制中期间**：返回 200 空表且审计 `rows=0`，导出物无任何"未锁定"提示。
3. **17b 重置密码守卫依赖目标当前角色**：目标角色被清空的窗口内，较低权限管理员可重置其密码（实测发生，但由并发改角色触发）。

## 未构成失败的观察

- `PAYSLIP` 与 `PERIOD_SHEET` 内容在当前单主体数据下完全一致（列、行相同）；符合"工资条只含工号/姓名/部门/项目/合计"的约定，但两者缺少区分度，产品上可再确认。
- 缺少必填参数时 Spring 返回通用文案「请求参数格式不正确」（如 `/reports/annual` 不传 groupBy、`/depts` 不传 companyId），而非字段级提示。
- 审计对空结果不落库（报表 VIEW 与导出 rows=0 的处理不一致：前者不写、后者写），属口径不统一而非错误。
